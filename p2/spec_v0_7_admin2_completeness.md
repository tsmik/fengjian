> 狀態：**補遺**。v0.5（主體）＋v0.6（資料合約）仍有效，本檔只新增「admin2 必須完整重現舊 admin」的原則與清單。
> 緣由：舊 admin 是 Mike 花十幾小時逐步摸索、請 CC 建起來的；其中沒有「想當然耳不必要」的功能。本檔修正先前「列缺口讓 Mike 砍」的錯誤框架。
> 依據盤點：`p2/old_admin_inventory.md`。

## 0. 核心原則（最高優先，凌駕個別判斷）

1. **admin2 必須完整重現舊 admin 的所有功能**，包含操作細節（刪除保護、被引用標籤、搬移、預設值、男女切換、dirty 追蹤等），不是只做「主要功能」。
2. **預設全部保留。任何功能的移除，都需要 Mike 明確指示**——舉證責任在「砍」，不在「留」。Claude／CC 不得自行假設某功能不必要、不得替舊功能排「重要性」而暗示可砍。
3. 這與本專案「老師原話逐字保留、不歸納壓縮」精神一致：**已存在且 Mike 驗證過的東西，預設保留。**
4. 例外：v0.6 §4.5 已明確除名的「條件文法層」項目（VETO/weight/深層巢狀/LR 節點/NOT 節點）——那是條件「怎麼組」的文法換代，經討論定案；**不等於可砍掉舊 admin 的「編輯功能區」**。兩者是不同層次，別混。

## 2. 敘述分組（section）＝一等公民（重要，修正先前輕忽）

**定義（Mike 原話精神）**：section（眉型/眉勢/眉位/眉質…、頂骨/枕骨/華陽骨…）**就是老師原來在講的「條件」**；觀察題目與勾選條件，是 Mike 把這些老師的指引**拆解**出來的下層。所以 section 是**老師語言/判讀骨架的承載單位**，不是「題目的分類標籤」。

**因此：**
- section **不是觀察庫的附屬功能**，而是與觀察題目同等的一等結構。admin2 觀察庫編輯器的核心層級＝**部位 → section → 觀察題 → 選項**。
- admin2 必須能完整管理 section：**建立/改名/刪除/排序、把題目在 section 間搬移**（對應舊 admin 既有能力）。
- `/app` 已大量用 section 組織呈現；P2 前台沿用，故 section 結構與順序不可丟。

**資料合約補充（更新 v0.6 §A.1）**：`observations/{obsId}` 正式納入 `section` 欄位（撈草稿時已帶入，未遺失）。
- 需**保留 section 在每部位內的排列順序**（舊資料是陣列順序；新結構要嘛存 order 索引、要嘛另存每部位的 section 順序清單）——不可只靠隨機集合順序。
- 現況：138 筆 obs 已帶 `part`＋`section`；缺的是 admin2「顯示/管理」介面，以及「順序」的正式保存。

## 3. 防止重建時悄悄丟東西：逐項核對 ＋ Mike 並排驗收

3. 驗收發現漏項＝補做，不是「之後再說」。

## 4. UI 原則：對齊 /app，不要工程風

- admin2 現在偏工程風，是因為先求「功能跑通」、未做外觀——順序正確。
- **新蓋的功能區（觀察庫等），從一開始就用 /app 的設計語言**（配色 static `#7A9E7E`／dynamic `#C17A5A`、Noto Serif TC、wabi-sabi 暖砂石質感），不要再生工程風。
- **整體視覺美化排在功能大致齊備後做一次 pass**，避免邊加分頁邊美化造成風格不一致、白做工。
